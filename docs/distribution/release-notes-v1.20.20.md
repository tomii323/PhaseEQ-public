# PhaseEQ v1.20.20 更新案内

PhaseEQ v1.20.20では、マルチウェイのFIRタップ長0の扱いを修正し、初回表示とLight／Interactiveグラフ切替を高速化しました。

## FIRタップ長0の修正

- FIR LR2／LR4などの帯域分割FIRに接続するウェイでは、タップ長0を「分割FIRから必要長を自動計算する指定」として維持します。
- 分割方式の切替や設定の再読込で、保存値0を固定タップ数へ書き換えたり、FIR OFFと誤判定したりしないよう修正しました。
- IIRのみ、スルー、全帯域でタップ長0の場合は、従来どおりFIR OFFです。FIR出力全体をOFFにした場合もFIRは生成しません。
- FIR LR2／LR4の自然長は、精度条件を保った近似値を先に評価し、必要な場合だけ従来の数値探索へ戻る方式にして計算時間を短縮しました。

## マルチウェイのグラフ表示

- 初回表示の依存初期化、FIR生成、表示用データ作成、グラフ描画を分離し、最初のグラフが表示されるまでの待ち時間を短縮しました。
- `Light`はAltairによる軽量表示、`Interactive`はPlotlyによる拡大・パン・ツールチップ対応を継続します。両モードは同じ確定済み計算結果を使用します。
- グラフ領域だけを再描画する構成へ変更し、表示モードの切替ではFIRや合成応答を再計算しません。
- Interactiveのブラウザー転送値だけを一時float32化し、元の計算精度、保存値、出力係数を変えずに転送量を約48～49%削減しました。
- Light／Interactiveの切替でも各グラフの高さと配置を維持し、後続の表やダウンロード欄が上下へ移動しないようにしました。

## 検証結果

- 同一条件のモード切替中央値は、Interactiveが約28%、Lightが約17%短縮しました。
- Lightの6グラフが揃うまでの中央値は、従来PNG表示と比べ約44%短縮しました。
- 4Way Stereo・96 kHz・4096点の高負荷条件で20往復し、画面位置、グラフ数、明示GC後のメモリー、実行ログが増加しないことを確認しました。
- Light位相グラフの過剰なDOM生成と、表示モード切替ごとに設定保存ログが増える問題も修正しました。

操作方法は[日本語操作ガイド](user-guide.md#composite-engine)をご覧ください。画像付き操作マニュアルはv1.20.15版を継続して同梱しています。
