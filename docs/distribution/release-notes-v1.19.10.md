# PhaseEQ v1.19.10 更新案内

PhaseEQ v1.19.10では、帯域分割・表示解析の共通化、編集時の待ち時間削減、ダウンロード操作の簡略化を行いました。Standaloneで帯域分割を選べない不具合も修正しています。

## 表示解析と操作速度

- PhaseEQのIR・Step・群遅延・Waveletの応答データを独立共通モジュールへ集約しました。IRとStepの時間原点を揃え、Stepは全長IRの積分後に切り出します。
- 表示用の「Display FFT」は等倍・2倍・4倍から選択できます。既定は等倍で、96 kHzでは96,001点です。倍率を上げると長い減衰の確認に使えますが、時間とメモリが増えます。FIRタップ数や出力係数は変わりません。
- 測定範囲外は表示のために推定し、スピーカー応答のDCを0とします。欠損した実測情報を復元する機能ではありません。位相のない測定の時間応答や、未設定Targetとの差分は代用生成しません。
- 未変更の入力処理・表示系列・出力準備をキャッシュで再利用します。表示点数は従来どおり1,024／2,048／4,096点から選び、保存・DSP処理のデータは間引きません。測定のoct平滑化設定も維持します。
- Complex Gainの窓平均を高速化し、EQ数値の連続入力では中間値ごとの全画面更新を抑えます。入力終了後に最新値の更新を開始する方式で、描画完了を一定時間以内に保証するものではありません。
- Export、IIR、Target、バックアップ、測定Session、Multiwayの出力は、準備ボタンを押さずダウンロード1回で生成・取得できます。設定を確定し、画面更新を待ってから操作してください。

## FIR生成と帯域分割

- Multiwayの帯域分割処理を独立共通モジュールへ移し、PhaseEQで基準クロス・overlap・方式・自然タップ数などを引き継ぎます。既存のMultiway構成別分割、IIR／FIR混在、LR2極性補償のロジックは維持します。
- 新規Standaloneの帯域分割は、基準クロスからcutoffと自然タップ数を自動計算します。旧設定の移行は明示操作で行います。
- FIR生成FFTはMultiwayと共通の偶数長を使います。96 kHz／351 tapsでは96,000点です。表示用の奇数FFTとは用途が異なります。
- Multiwayの最終FIR投影の余分な1 sample遅延、および合成IRグラフの時間軸ずれを修正しました。
- Waveletの演算コアを共通化し、旧2ファイルと未使用ヘルパーを削除しました。PhaseEQの新しい表示解析入口をComposite／Multiwayへ適用する変更は、今回の対象外です。

## 不具合修正・設定

- Standaloneで保存済みMultiway Recipeがある場合も、Output Band SplitのPresetを選べます。選択だけではRecipeを変更せず、Apply時に単独設定へ置き換えます。接続中の制限は維持します。
- 消去済み数値widgetの遅延callbackによる停止と、再読み込み後の入力キャッシュのPicklingErrorを修正しました。
- Auto IIRに生成条件を初期値へ戻す操作を追加しました。生成済みEQや編集中Channelは削除せず、自動再生成もしません。

## 更新前後の注意

1. 編集内容を保存し、必要に応じてWorking Session ZIPでバックアップしてください。
2. 更新後はPhaseEQとComposite Engineの両方を終了して再起動してください。旧Waveletモジュールの一時メモリ／pickle参照は引き継げません。保存済み測定NPZは維持します。
3. 既存作業を再計算・再出力すると、生成グリッドや中心遅延の修正により係数が変わる場合があります。完成済みFIRファイルは書き換えません。旧形式FIR Recipeは旧計算条件で再生成します。
4. 新形式FIR Recipeを他PCへ渡す場合は、受取側もv1.19.10以降の対応版へ更新してください。

操作の詳細は[利用者ガイド](user-guide.md)、出力内容は[出力ファイル仕様](output-format.md)を参照してください。
